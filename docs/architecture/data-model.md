# Basis data model

This document turns [ADR 0001](0001-canonical-knowledge-model.md) into a persistence
contract. It covers the core schema needed for ingest, evidence, graph projection, review, search,
and Explorer integration.

## 1. Storage boundaries

| Store | Canonical | Contents |
| --- | --- | --- |
| `data/basis.db` | Yes | accounts, KBs, documents, chunks, ledger, review, mappings, decisions, audit; external entity refs & sync outbox ([ADR 0003](0003-lakehouse-datasets.md) §18) |
| `data/blobs/{kb_id}/...` | Yes | original uploaded/connector payloads, content-addressed |
| `data/graphs/{kb_id}.json` | No | rebuildable ContextGraph projection |
| `data/indexes/{kb_id}/...` | No | vector/search indexes |
| process memory | No | Explorer sessions, search caches, WS connections |

SQLite is the initial canonical database. Schema choices must remain portable to PostgreSQL:
UUIDs and timestamps are represented as `TEXT` initially, JSON as canonical JSON text, and booleans
as `INTEGER CHECK (... IN (0,1))`.

## 2. Global conventions

- IDs are lowercase UUID strings generated by the application.
- Timestamps are UTC RFC3339 with timezone.
- Every KB-owned table has an explicit `kb_id`; authorization never infers KB only through a long
  join chain.
- Semantic records are append/invalidate/supersede. In-place updates are reserved for operational
  state such as job progress.
- `created_at` answers when a row was recorded. `valid_from`/`valid_to` answer when it was true in
  the represented world and may be null.
- `invalidated_at IS NULL` means active on the record axis.
- JSON fields have a documented schema and serialize with sorted keys in tests.
- User-facing resources use opaque IDs. Filenames and IDs never determine an unrestricted path.

## 3. Migration system

Replace the single expanding `_migrate()` script with ordered migrations:

```text
basis/admin/migrations/
  0001_admin.sql
  0002_knowledge_ledger.sql
  0003_search_review.sql
```

Required metadata:

```sql
CREATE TABLE schema_migrations (
  version INTEGER PRIMARY KEY,
  applied_at TEXT NOT NULL,
  checksum TEXT NOT NULL
);
```

Rules:

- migrations run under an exclusive application startup lock;
- each migration is atomic;
- an applied migration file is immutable;
- startup fails on checksum mismatch or migration failure;
- tests create a database from zero and upgrade a fixture from the previous version;
- destructive changes use create/copy/verify/rename, not ad-hoc column deletion.

## 4. Existing administrative tables

Keep `users`, `knowledge_bases`, `kb_members`, `settings`, and `audit_log`, with these changes.

### 4.1 Session and API tokens are separate

The existing `tokens` table stores login sessions. Rename it logically and eventually physically to
`sessions`:

```sql
sessions(
  token_hash TEXT PRIMARY KEY,
  user_id TEXT NOT NULL REFERENCES users(id),
  created_at TEXT NOT NULL,
  expires_at TEXT,
  last_seen_at TEXT
)
```

API tokens are separate:

```sql
api_tokens(
  id TEXT PRIMARY KEY,
  token_hash TEXT NOT NULL UNIQUE,
  token_secret TEXT,
  user_id TEXT NOT NULL REFERENCES users(id),
  name TEXT NOT NULL,
  scope TEXT NOT NULL,              -- read | write
  kb_ids_json TEXT NOT NULL,        -- [] means no KB, never means all
  created_at TEXT NOT NULL,
  expires_at TEXT,
  last_used_at TEXT,
  revoked_at TEXT
)
```

`token_secret` stores the plaintext bearer value for owner re-copy in the admin UI (protect the
SQLite file accordingly). Auth uses `token_hash` only. Revoking clears `token_secret`. Logs never
expose secrets.

### 4.2 Knowledge base fields

Add:

```text
governance_enabled INTEGER NOT NULL DEFAULT 0
default_locale TEXT NOT NULL DEFAULT 'zh'
ontology_lang TEXT NOT NULL DEFAULT 'zh'
extraction_profile_json TEXT NOT NULL DEFAULT '{}'
ontology_edit_role TEXT NOT NULL DEFAULT 'editor'
deleted_at TEXT
```

Visibility values are exactly `open` and `restricted`, matching current code. `open` grants
unauthenticated access only if a future public API explicitly supports it; today it means visible
to authenticated users and remains read-only unless membership grants a higher role.

### 4.3 Audit log

Extend `audit_log` with:

```text
kb_id TEXT
request_id TEXT
category TEXT NOT NULL DEFAULT 'platform'
result TEXT NOT NULL DEFAULT 'success'
```

`detail` stays JSON text and must be secret-filtered. Audit rows are append-only.

## 5. Sources, documents, versions, and blobs

```sql
CREATE TABLE ingest_sources (
  id TEXT PRIMARY KEY,
  kb_id TEXT NOT NULL REFERENCES knowledge_bases(id),
  kind TEXT NOT NULL,
  name TEXT NOT NULL,
  config_json TEXT NOT NULL,
  secret_ref TEXT,
  enabled INTEGER NOT NULL DEFAULT 1 CHECK (enabled IN (0,1)),
  created_by TEXT NOT NULL REFERENCES users(id),
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  deleted_at TEXT
);

CREATE TABLE documents (
  id TEXT PRIMARY KEY,
  kb_id TEXT NOT NULL REFERENCES knowledge_bases(id),
  source_id TEXT REFERENCES ingest_sources(id),
  external_key TEXT,
  title TEXT NOT NULL,
  mime_type TEXT NOT NULL,
  current_version_id TEXT,
  created_by TEXT REFERENCES users(id),
  created_at TEXT NOT NULL,
  deleted_at TEXT
);

CREATE UNIQUE INDEX documents_source_key_active
  ON documents(kb_id, source_id, external_key)
  WHERE external_key IS NOT NULL AND deleted_at IS NULL;

CREATE TABLE document_versions (
  id TEXT PRIMARY KEY,
  kb_id TEXT NOT NULL REFERENCES knowledge_bases(id),
  document_id TEXT NOT NULL REFERENCES documents(id),
  version_no INTEGER NOT NULL,
  sha256 TEXT NOT NULL,
  blob_key TEXT NOT NULL,
  byte_size INTEGER NOT NULL CHECK (byte_size >= 0),
  source_time TEXT,
  source_time_kind TEXT,            -- content | source | upload | none
  status TEXT NOT NULL,
  error_code TEXT,
  error_detail_json TEXT,
  created_at TEXT NOT NULL,
  ready_at TEXT,
  UNIQUE(document_id, version_no)
);
```

Allowed version status:

`queued`, `parsing`, `chunking`, `embedding`, `extracting`, `ready`, `failed`, `stale`.

Blob key is content-addressed, for example
`{kb_id}/{sha256[0:2]}/{sha256}`. Original filename is metadata, never the path.

**Ingest source `kind` (today):** `webhook`, `http_poll`, `git` (GitHub raw paths).

**Planned structured kinds ([ADR 0003](0003-lakehouse-datasets.md)):** `postgres_table`, `tabular_upload`, `rest_records`
(mapping table rows directly into canonical `entities` and `statements`, plus optional bidirectional write-back).

## 7. Entities and names

```sql
CREATE TABLE entities (
  id TEXT PRIMARY KEY,
  kb_id TEXT NOT NULL REFERENCES knowledge_bases(id),
  canonical_label TEXT,
  description TEXT,
  entity_kind TEXT NOT NULL DEFAULT 'named',
  created_at TEXT NOT NULL,
  invalidated_at TEXT
);

CREATE TABLE entity_names (
  id TEXT PRIMARY KEY,
  kb_id TEXT NOT NULL REFERENCES knowledge_bases(id),
  entity_id TEXT NOT NULL REFERENCES entities(id),
  value TEXT NOT NULL,
  normalized_value TEXT NOT NULL,
  language TEXT,
  evidence_id TEXT,
  recorded_at TEXT NOT NULL,
  invalidated_at TEXT
);

CREATE INDEX entity_names_lookup
  ON entity_names(kb_id, normalized_value)
  WHERE invalidated_at IS NULL;
```

`entity_kind` is `named` or `described`. Described entities are document-local and have no required
name. Same names are intentionally non-unique.

## 8. Open statements and evidence

```sql
CREATE TABLE statements (
  id TEXT PRIMARY KEY,
  kb_id TEXT NOT NULL REFERENCES knowledge_bases(id),
  subject_id TEXT NOT NULL REFERENCES entities(id),
  surface_phrase TEXT NOT NULL,
  object_entity_id TEXT REFERENCES entities(id),
  object_value TEXT,
  object_datatype TEXT,
  confidence REAL,
  status TEXT NOT NULL,
  proposed_by TEXT NOT NULL,
  recorded_at TEXT NOT NULL,
  invalidated_at TEXT,
  supersedes_id TEXT REFERENCES statements(id),
  CHECK ((object_entity_id IS NULL) <> (object_value IS NULL))
);

CREATE TABLE statement_evidence (
  id TEXT PRIMARY KEY,
  kb_id TEXT NOT NULL REFERENCES knowledge_bases(id),
  statement_id TEXT NOT NULL REFERENCES statements(id),
  chunk_id TEXT NOT NULL REFERENCES chunks(id),
  quote TEXT NOT NULL,
  quote_start INTEGER,
  quote_end INTEGER,
  created_at TEXT NOT NULL,
  UNIQUE(statement_id, chunk_id, quote_start, quote_end)
);

CREATE TABLE statement_qualifiers (
  id TEXT PRIMARY KEY,
  kb_id TEXT NOT NULL REFERENCES knowledge_bases(id),
  statement_id TEXT NOT NULL REFERENCES statements(id),
  role TEXT NOT NULL,
  value TEXT,
  entity_id TEXT REFERENCES entities(id),
  CHECK ((entity_id IS NULL) <> (value IS NULL))
);

CREATE TABLE time_mentions (
  id TEXT PRIMARY KEY,
  kb_id TEXT NOT NULL REFERENCES knowledge_bases(id),
  statement_id TEXT NOT NULL REFERENCES statements(id),
  chunk_id TEXT NOT NULL REFERENCES chunks(id),
  text TEXT NOT NULL,
  char_start INTEGER NOT NULL,
  char_end INTEGER NOT NULL
);
```

Statement status: `pending`, `confirmed`, `rejected`, `invalidated`, `superseded`.
`proposed_by`: `pattern`, `ml`, `llm`, `connector`, `user`, `chat`, or `legacy_import`.

The application enforces that evidence quote offsets locate `quote` inside the chunk. If offsets
cannot be supplied for a legacy import, the origin is `legacy_import` and no quote is fabricated.

## 9. Ontology mappings and facts

```sql
CREATE TABLE mappings (
  id TEXT PRIMARY KEY,
  kb_id TEXT NOT NULL REFERENCES knowledge_bases(id),
  signature TEXT NOT NULL,
  target_uri TEXT,
  target_kind TEXT NOT NULL,       -- property | class | none
  direction TEXT NOT NULL,         -- forward | reverse | n/a
  status TEXT NOT NULL,
  actor_id TEXT REFERENCES users(id),
  why TEXT,
  created_at TEXT NOT NULL,
  invalidated_at TEXT,
  supersedes_id TEXT REFERENCES mappings(id)
);

CREATE UNIQUE INDEX mapping_active_signature
  ON mappings(kb_id, signature)
  WHERE status = 'confirmed' AND invalidated_at IS NULL;

CREATE TABLE typed_facts (
  id TEXT PRIMARY KEY,
  kb_id TEXT NOT NULL REFERENCES knowledge_bases(id),
  subject_id TEXT NOT NULL REFERENCES entities(id),
  predicate_uri TEXT NOT NULL,
  object_entity_id TEXT REFERENCES entities(id),
  object_value TEXT,
  object_datatype TEXT,
  from_statement_id TEXT REFERENCES statements(id),
  mapping_id TEXT REFERENCES mappings(id),
  import_provenance_json TEXT,
  confidence REAL,
  valid_from TEXT,
  valid_to TEXT,
  recorded_at TEXT NOT NULL,
  invalidated_at TEXT,
  supersedes_id TEXT REFERENCES typed_facts(id),
  CHECK ((object_entity_id IS NULL) <> (object_value IS NULL)),
  CHECK (from_statement_id IS NOT NULL OR import_provenance_json IS NOT NULL)
);
```

Mapping status: `proposed`, `confirmed`, `rejected`, `superseded`.
`target_kind=none` is a confirmed human decision that no ontology term fits and prevents repeated
automatic proposals until superseded.

Derived facts and proof edges use separate `derived_facts` and `fact_derivations` tables with the
same fact shape. They never share IDs with asserted facts.

## 13. Projection identity

Every projected graph element carries stable ledger references.

Node properties:

```json
{
  "sema_entity_id": "uuid",
  "projection_revision": 42,
  "node_kind": "entity"
}
```

Edge properties:

```json
{
  "sema_statement_id": "uuid-or-null",
  "sema_typed_fact_id": "uuid-or-null",
  "sema_derived_fact_id": "uuid-or-null",
  "layer": "open|typed|derived",
  "evidence_ids": ["uuid"],
  "projection_revision": 42
}
```

Graph node IDs are not generated from labels. This prevents same-name collisions and allows rename
without graph identity changes.

Projection metadata is stored separately:

```sql
CREATE TABLE projection_state (
  kb_id TEXT PRIMARY KEY REFERENCES knowledge_bases(id),
  revision INTEGER NOT NULL DEFAULT 0,
  schema_version INTEGER NOT NULL,
  status TEXT NOT NULL,
  last_built_at TEXT,
  last_error_code TEXT
);
```

Status: `ready`, `dirty`, `building`, `failed`.

## 14. Deletion and retention

- KB deletion is soft in canonical tables first, then an asynchronous purge removes blobs,
  projections, indexes, and eligible rows after the configured retention period.
- Document deletion invalidates active statements only when no other live evidence remains.
- User deactivation revokes sessions/API tokens but preserves audit attribution.
- Audit is retained indefinitely by default; alerts and transient jobs have configurable retention.
- Hard purge writes an audit event before physical removal.

## 15. Transactions

The following are single database transactions:

- document/version creation + ingest job creation;
- review decision + statement/mapping/merge transition + audit event;
- mapping confirmation + typed projection row changes;
- entity merge/revert + decision/audit records;
- chat `remember` + pending statement/review item.

Graph/vector projection runs after commit. Failure marks `projection_state=dirty|failed` and queues a
rebuild; canonical data remains committed.

## 16. Required indexes

At minimum:

- every child foreign key used in deletion/lookup;
- `(kb_id, status, created_at)` on jobs, review items, statements, facts;
- `(kb_id, normalized_value)` on active entity names;
- `(version_id, ordinal)` on chunks;
- `(statement_id)` and `(chunk_id)` on evidence;
- `(kb_id, predicate_uri)` on active typed facts;
- `(kb_id, created_at)` on audit and decisions.

Query plans for graph projection, review list, document list, and search citation resolution are
captured in tests before production-scale rollout.

## 17. Compatibility and migration

Current data is migrated as follows:

- existing users, sessions, KBs, members, settings, and audit rows are preserved;
- each graph `document` node becomes a document/version marked `legacy_import`;
- graph entity nodes get generated UUID-backed entities while retaining old node ID in metadata;
- graph edges become confirmed open statements with `proposed_by=legacy_import`;
- no quote/evidence is invented;
- projection is rebuilt and compared by node/edge counts plus sampled semantic content;
- original graph JSON is retained until migration verification passes.

The migration command must support dry-run, report unmappable nodes/edges, and be idempotent.

Structured source binding and bidirectional entity sync ([ADR 0003](0003-lakehouse-datasets.md)) plan migration
**`0011_entity_external_sync.sql`** (tables in §18) when implementation begins; no empty tables are applied beforehand.

## 18. Structured sources and bidirectional entity sync (F-LAKE / F-OPS — planned DDL)

**Status:** planned schema ([ADR 0003](0003-lakehouse-datasets.md)). Ships as migration `0011_entity_external_sync.sql` when structured source sync implementation starts.

Instead of a parallel Parquet warehouse, structured database rows map directly into canonical **`entities`**,
**`statements`**, and **`typed_facts`**. Three tables track column mappings, external primary-key identity, and outbound
write-back to business databases.

### 18.1 Basis Connector runtime tables (migrated from AnyConnect, `kb_id === app_id`)

Because **1 Knowledge Base (`kb_id`) === 1 AnyConnect App (`app_id`)**, AnyConnect’s `apps` table is eliminated—its
policy columns (`allowed_providers`, `action_policy_json`) live on the KB connector policy, and AnyConnect’s
`connections`, `oauth_client_configs`, `oauth_states`, and `runs` tables migrate directly into Basis keyed by `kb_id`:

```sql
CREATE TABLE IF NOT EXISTS kb_connector_policies (
  kb_id TEXT PRIMARY KEY REFERENCES knowledge_bases(id) ON DELETE CASCADE,
  allowed_providers_json TEXT NOT NULL DEFAULT '"*"', -- "*" or ["postgres", "airtable", "github", ...]
  action_policy_json TEXT NOT NULL DEFAULT '{}',      -- {"allowedActions": [...], "blockedActions": [...]} (F-OPS-02)
  updated_at TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS kb_connections (
  kb_id TEXT NOT NULL REFERENCES knowledge_bases(id) ON DELETE CASCADE,
  service TEXT NOT NULL,              -- provider id, e.g. "postgres", "mysql", "airtable", "hubspot"
  connection_name TEXT NOT NULL,      -- "default" for KB-level sync, or Basis users.id for per-user OAuth
  value_encrypted TEXT NOT NULL,      -- AES-256-GCM encrypted credential / OAuth token JSON
  revision INTEGER NOT NULL DEFAULT 1,
  updated_at TEXT NOT NULL,
  PRIMARY KEY (kb_id, service, connection_name)
);

CREATE TABLE IF NOT EXISTS kb_oauth_configs (
  kb_id TEXT NOT NULL REFERENCES knowledge_bases(id) ON DELETE CASCADE,
  service TEXT NOT NULL,
  value_encrypted TEXT NOT NULL,      -- custom OAuth client_id / client_secret for this KB
  updated_at TEXT NOT NULL,
  PRIMARY KEY (kb_id, service)
);

CREATE TABLE IF NOT EXISTS kb_connector_runs (
  id TEXT PRIMARY KEY,
  kb_id TEXT NOT NULL REFERENCES knowledge_bases(id) ON DELETE CASCADE,
  service TEXT NOT NULL,
  action_id TEXT NOT NULL,            -- e.g. "postgres.list_records", "hubspot.update_contact"
  connection_name TEXT NOT NULL DEFAULT 'default',
  started_at TEXT NOT NULL,
  completed_at TEXT NOT NULL,
  ok INTEGER NOT NULL,
  value_json TEXT NOT NULL            -- redacted input/output/timing snapshot
);

CREATE INDEX IF NOT EXISTS idx_kb_connector_runs_kb_started
  ON kb_connector_runs(kb_id, started_at DESC);
```

### 18.2 Table/Resource-to-ontology mappings and external entity identity

All structured sources—whether relational databases (`postgres`, `mysql`) or SaaS applications (`airtable`, `hubspot`,
`jira`, `notion`)—are unified under a single **Provider + Read/Write Action** contract (`ingest_sources.kind = 'connector'`).

```sql
CREATE TABLE IF NOT EXISTS source_table_mappings (
  id TEXT PRIMARY KEY,
  kb_id TEXT NOT NULL REFERENCES knowledge_bases(id) ON DELETE CASCADE,
  source_id TEXT NOT NULL REFERENCES ingest_sources(id) ON DELETE CASCADE,
  external_table TEXT NOT NULL,       -- table or resource key, e.g. "public.suppliers" or "contacts"
  read_action_id TEXT NOT NULL,       -- e.g. "postgres.list_records" or "hubspot.list_contacts"
  write_action_id TEXT,               -- e.g. "postgres.update_record" or "hubspot.update_contact"
  action_params_json TEXT NOT NULL DEFAULT '{}', -- static input params for the action (e.g. schema/table or baseId)
  records_json_path TEXT NOT NULL DEFAULT 'records', -- key in action output holding the row array
  primary_key_column TEXT NOT NULL,   -- e.g. "supplier_id" or "id"
  label_column TEXT NOT NULL,         -- field mapped to entities.canonical_label, e.g. "company_name"
  target_class_uri TEXT NOT NULL,     -- ontology class URI (written as rdf:type in typed_facts)
  column_mappings_json TEXT NOT NULL, -- JSON array of ColumnMappingSpec (see §18.4)
  sync_direction TEXT NOT NULL DEFAULT 'inbound', -- 'inbound' | 'bidirectional'
  writeback_mode TEXT NOT NULL DEFAULT 'review',  -- 'review' | 'direct'
  max_rows INTEGER NOT NULL DEFAULT 10000,
  status TEXT NOT NULL DEFAULT 'active',          -- 'active' | 'paused'
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE(kb_id, source_id, external_table)
);

CREATE INDEX IF NOT EXISTS idx_source_table_mappings_kb_source
  ON source_table_mappings(kb_id, source_id);

CREATE TABLE IF NOT EXISTS entity_external_refs (
  id TEXT PRIMARY KEY,
  kb_id TEXT NOT NULL REFERENCES knowledge_bases(id) ON DELETE CASCADE,
  entity_id TEXT NOT NULL REFERENCES entities(id) ON DELETE CASCADE,
  source_id TEXT NOT NULL REFERENCES ingest_sources(id) ON DELETE CASCADE,
  mapping_id TEXT NOT NULL REFERENCES source_table_mappings(id) ON DELETE CASCADE,
  external_table TEXT NOT NULL,
  external_pk TEXT NOT NULL,          -- stringified upstream primary key
  row_hash TEXT NOT NULL,             -- SHA-256 hex of canonical JSON of mapped columns (§18.5)
  last_synced_at TEXT NOT NULL,
  deleted_upstream_at TEXT,
  UNIQUE(kb_id, source_id, external_table, external_pk)
);

CREATE INDEX IF NOT EXISTS idx_entity_external_refs_entity
  ON entity_external_refs(kb_id, entity_id);
```

### 18.3 Outbound write-back outbox (Basis → Provider Write Action)

Note: references **`agent_decisions(id)`** (actual table name in `0002_knowledge_ledger.sql`), not `decisions(id)`.

```sql
CREATE TABLE IF NOT EXISTS entity_sync_outbox (
  id TEXT PRIMARY KEY,
  kb_id TEXT NOT NULL REFERENCES knowledge_bases(id) ON DELETE CASCADE,
  entity_id TEXT NOT NULL REFERENCES entities(id) ON DELETE CASCADE,
  external_ref_id TEXT NOT NULL REFERENCES entity_external_refs(id) ON DELETE CASCADE,
  statement_id TEXT REFERENCES statements(id) ON DELETE SET NULL,
  typed_fact_id TEXT REFERENCES typed_facts(id) ON DELETE SET NULL,
  action_kind TEXT NOT NULL,          -- 'update_attributes' | 'declared_action'
  patch_json TEXT NOT NULL,           -- JSON object of OutboxPatchSpec (see §18.3)
  status TEXT NOT NULL,               -- 'pending_review' | 'queued' | 'synced' | 'failed' | 'rejected'
  review_item_id TEXT REFERENCES review_items(id) ON DELETE SET NULL,
  decision_id TEXT REFERENCES agent_decisions(id) ON DELETE SET NULL,
  job_id TEXT REFERENCES jobs(id) ON DELETE SET NULL,
  error_code TEXT,
  error_detail_json TEXT,
  created_by TEXT REFERENCES users(id),
  created_at TEXT NOT NULL,
  synced_at TEXT
);

CREATE INDEX IF NOT EXISTS idx_entity_sync_outbox_kb_status
  ON entity_sync_outbox(kb_id, status, created_at);
```

### 18.5 Canonical `row_hash` algorithm & unified Action execution

- **Deterministic `row_hash`:** build a dict containing only `{label_column: val, **{m["column"]: val for m in column_mappings}}` with `None` preserved and dates/decimals converted to ISO/string; serialize with `json.dumps(payload, sort_keys=True, ensure_ascii=False, separators=(",", ":"))`; compute `hashlib.sha256(raw.encode("utf-8")).hexdigest()`.
- **Inbound pull (Provider Read Action → Basis):** invoke `read_action_id` (whether `postgres.list_records` or `hubspot.list_contacts`) to obtain `records: list[dict]`, and compare each record against `entity_external_refs.row_hash`. Unchanged rows are skipped. Changed fields supersede previous `proposed_by = 'connector'` statements/typed_facts in a single transaction—unless an active statement on the same `(subject_id, surface_phrase)` was authored by `user` or `agent` (`proposed_by IN ('user', 'agent')`), which triggers `scan_statement_conflicts()` (`kind = 'statement_conflict'` in `review_items`).
- **Outbound write-back (Basis → Provider Write Action):** when `writeback_mode = 'review'`, editing a writable mapped attribute creates a `pending_review` outbox row and a `review_items` entry (`kind = 'entity_writeback'`, `subject_type = 'entity_sync_outbox'`, `subject_id = outbox.id`). Approving the review item records an `agent_decisions` row, transitions the outbox row to `queued`, and enqueues a `jobs` worker (`kind = 'entity_writeback'`), which executes `write_action_id` with `patch_json.action_input` (under the hood, the `postgres`/`mysql` provider uses **SQLAlchemy 2.0 Core** `Table` + `update()`, while SaaS providers call their AnyConnect executor), recomputes `entity_external_refs.row_hash` (preventing echo loops), and marks `status = 'synced'`.
- **Framework discipline:** all JSON payloads in §18.3 are validated via **Pydantic v2** models (`basis/domain/kb/structured_models.py`), and the built-in `postgres`/`mysql` provider actions use **`sqlalchemy.inspect(engine)`** and **SQLAlchemy Core** rather than hand-written SQL.
- **Entity / Source deletion cascade:** `basis/domain/kb/entity_delete.py` must delete `entity_sync_outbox` and `entity_external_refs` rows for `entity_id` (and `review_items` with `subject_type = 'entity_sync_outbox'`) before deleting `entities`.
